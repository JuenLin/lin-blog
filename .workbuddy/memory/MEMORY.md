# 项目长期约定

## 环境变量文件规则（用户明确要求，务必遵守）

- `backend/.env`：**只放真实值**，不进 Git（`backend/.gitignore` 已忽略）。
- `backend/.env.example`：**只放占位符**（`{{DB_USER}}` / `{{DB_PASSWORD}}` / `{{DB_NAME}}` / `{{JWT_SECRET}}`）。
- 两者**用途不同，禁止同源覆盖** —— 不允许把 `.env` 复制成 `.env.example`，也不允许用 `.env.example` 覆盖 `.env`。
- 后果提醒：一旦 `.env` 被占位符污染，所有 migrate / 启动都会报 `P1000 Authentication failed ... for {{DB_USER}}`。

## 敏感信息

- `JWT_SECRET`、数据库密码：**不在任何回复、日志、代码块里输出**。需要引用时用「已设置」或长度代替。

## 项目方向（2026-09-29 确定）

- 做**博客项目**，参考 CSDN。核心业务：发文章、文章列表（博客广场）、文章详情、评论互动。
- **MVP 范围**：只做文章 CRUD + 评论（发表 / 列表）。**明确不做**：点赞、收藏、标签、搜索、评论删除、用户管理接口（`/api/users` 保持未实现）。
- 推进顺序（用户定的流程）：**先 API 草案 → 确认后设计表结构写 docs/DB.md → 确认后一次性 migrate → 后端按 API.md 实现 → 前端按 API.md 做 MSW mock**。禁止提前建表、禁止超出 MVP 的接口。

## 协作方式

- 用户会自己改动 `docs/AI_CONTRACT.md`。涉及契约内容每次都必须重读，禁止引用会话早期读到的缓存版本（曾因此做出自相矛盾的错误汇报）。
- 列出问题时不要猜测原因，先做多通道验证，把客观事实摆出来。
- 删除文件前先确认引用为零。
